Featured Projects

NUTMEG! - Commercial Release

I worked as a Junior Programmer on NUTMEG!, a nostalgic football management game at Sumo Digital. One of my favourite parts of this project was building systems that brought the retro TV aesthetic to life while making life easier for our writers and artists:

CRT TV Shader & Teletext System

I created a custom CRT shader in HLSL featuring chromatic aberration, animated scanlines, vignette, and pixelation. The goal was to nail that nostalgic 80s feel and really immerse players in the retro atmosphere.

I built a teletext rendering system that read actual TTI files and emulated them on surface materials. To keep memory usage down, I designed the system to create one template per style and dynamically overwrite it rather than storing multiple instances that we'd only see once. This was a balance between our target SteamDeck platform's performance vs memory.

I also implemented offscreen texture rendering for the flip-score clocks, which drew the correct number as the animation completed. I used the offscreen texture to draw custom team colours on the clocks. This took the workload off the artists so they didn't have to create each clock's custom texture.

Python News Article Tool

I developed a Python tool using Tkinter to help our professional writers create in-game news articles quickly and efficiently. The UI let them create/edit/delete articles, input real-world dates (which auto-converted to our in-game calendar), and preview exactly how they'd appear in-game. This avoided editing the JSON directly or launching the game.

This streamlined the writing team's workflow and added built-in JSON validation. Articles were saved to a single JSON file in the correct directory that our TV system could read directly.

Dynamic Match Highlights System

Using std::format, I created an algorithm that analysed weekly match results and intelligently categorised them (hat-tricks, big wins, promotion/relegation battles, close matches, nil-nils, etc.). I found that most of the matches were boring nil-nils so I made the system prioritise exciting types and limit each type to two features per week.

To further prevent staleness and repeated dialogue, each category had a pool of different headlines and body text that cycled through without repeating.

Data-Driven Stadium Leveling System

I built a stadium upgrade system where stands and facilities change as the player levels up. It is fully data-driven through JSON and CSV configuration to avoid hardcoding which assets appear at which levels.

I made all stadium assets load upfront and only become visible when within their configured level range. I chose this approach as it preserves memory contiguity and avoids frequent runtime memory allocation and deletion.

I set this up so our environmental artist could edit the JSON directly and add their modular assets. I also recommended that they bake local transformation offsets into the assets themselves since the stadium doesn't move. This saved us from tedious transformation adjustments later.

Stadium Preview Tool (ImGui)

To help our environmental artist visualise how facility slots and buildings would look at different stadium levels, I created an ImGui debug command that let them cycle through all levels instantly. This streamlined the workflow for everyone who was working on stadium levelling.

Facilities & Leveling Progression

Working closely with our designer and director, I implemented the facilities purchasing system, where players unlock more slots as they level up their stadium. Players can buy levels and facilities once per week, with a tier-up available every 5 levels, between seasons. This created a nice sense of progression tied to the core game loop.
